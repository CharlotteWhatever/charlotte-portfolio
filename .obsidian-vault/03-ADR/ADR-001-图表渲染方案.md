# ADR-001：信息图表渲染方案选择

> 日期：2026-07-21 | 状态：已决策 | 决策人：Charlotte + Claude (PM)

## 背景

Professional Journey 板块需要从纯文字时间线改为信息图表。需要选择图表渲染技术方案。

## 方案评估

### 方案 A：纯 CSS Flexbox/Grid + 内联 SVG 箭头 ✅ 选择

**描述**：用 CSS 布局排布节点卡片，节点间用 `<svg>` 元素画箭头。

| 优点 | 缺点 |
|------|------|
| 零依赖，与1.0架构一致 | 复杂图形（雷达图、曲线）需手动计算坐标 |
| 响应式天然支持 | 不支持复杂动画 |
| SEO 友好（DOM 节点可见） | — |
| 可访问性好（语义化 HTML） | — |
| 复用现有 CSS 变量和阴影系统 | — |

### 方案 B：HTML Canvas

**描述**：用 `<canvas>` JS 绘制整个图表。

| 优点 | 缺点 |
|------|------|
| 灵活绘制任意图形 | 需要 JS 动态计算布局 |
| 适合复杂数据可视化 | 响应式需要手动重绘 |
| — | SEO 不友好（canvas 内容不可索引） |
| — | 可访问性差（需要额外 ARIA 标注） |
| — | 引入新的技术栈，与1.0架构不一致 |

### 方案 C：第三方库（ECharts / D3.js）

**描述**：引入 JS 可视化库绘制图表。

| 优点 | 缺点 |
|------|------|
| 图表类型丰富 | 破坏零依赖原则 |
| 开箱即用的交互 | 增加 ~300KB+ 加载体积 |
| — | 样式可能与 Neumorphism 冲突 |
| — | 学习成本 |

## 决策

**选择方案 A：纯 CSS + 内联 SVG**

理由：
1. 与1.0「零框架」架构一致
2. 信息图表以流程线+标签为主，不需要复杂统计图形
3. CSS Flexbox 水平排列天然适配 5 节点流程
4. SVG 箭头简单（`<line>` + `<polygon>`）
5. 响应式用 CSS `@media` 即可

## 后果

- 需要手动计算 SVG 箭头的起止坐标（桌面/平板/移动三个断点）
- 能力标签用 CSS 样式而非 SVG 绘制
- 后续如果需要雷达图等复杂图形，可在该节点内嵌入独立 SVG
