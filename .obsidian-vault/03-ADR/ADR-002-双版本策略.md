# ADR-002：桌面版 vs 移动版信息图表策略

> 日期：2026-07-21 | 状态：已决策 | 决策人：Charlotte + Claude (PM)

## 背景

用户要求同时开发桌面版和移动版信息图表，后续二选一或保留双版本响应式。

## 方案评估

### 方案 A：单一响应式布局 ✅ 选择

**描述**：一套 HTML，通过 CSS `@media` 在不同断点切换布局。

| 优点 | 缺点 |
|------|------|
| 单一代码源 | 桌面/移动版设计差异大时 CSS 可能复杂 |
| i18n 数据不重复 | — |
| 维护成本低 | — |
| 用户只需对比查看不同宽度 | — |

### 方案 B：两套独立 HTML 片段

**描述**：`#experience-desktop` 和 `#experience-mobile` 两个独立区域，通过 `display:none` 切换。

**不选择**：代码重复、维护两份 i18n、不符合响应式设计原则。

### 方案 C：JS 动态渲染

**描述**：JS 检测屏幕宽度，动态生成不同的 DOM 结构。

**不选择**：过度工程化，与零框架理念冲突。

## 决策

**选择方案 A：单一响应式布局**

断点策略：
- `>= 1024px`：桌面版 — 水平流程泳道图
- `768px - 1023px`：平板版 — 两行排列（3+2 节点）
- `< 768px`：移动版 — 纵向叙事滚动

用户通过缩放浏览器窗口即可对比桌面/移动效果。

## 后果

- CSS 需要处理三个断点的布局切换
- SVG 箭头需要三套坐标（或使用相对定位避免硬编码坐标）
- 移动端纵向布局使用 `scroll-snap` 提升滑动体验
